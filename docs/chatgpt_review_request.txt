# CONTEXTE DU CHALLENGE - DEMANDE D'AVIS CRITIQUE SUR L'EDA

## 1. PRÉSENTATION DU CHALLENGE

### Objectif
Développer un algorithme de classification multi-label pour prédire les tags algorithmiques associés à des exercices de programmation issus de Codeforces.

### Contraintes
- **Délai** : 4 jours (rendu lundi)
- **Environnement** : CPU uniquement (pas de GPU)
- **Performance** : Temps de prédiction < 10 secondes par exemple
- **Focus** : 8 tags prioritaires parmi 37 tags totaux

### Tags Prioritaires
```
['math', 'graphs', 'strings', 'number theory', 'trees', 'geometry', 'games', 'probabilities']
```

### Livrables Attendus
1. CLI Python pour prédiction et évaluation
2. Code d'entraînement du modèle
3. Slides de présentation
4. Métriques par tag (identifier quels tags sont les mieux prédits)

---

## 2. STRUCTURE DU DATASET

### Vue d'Ensemble
- **4982 échantillons** (exercices uniques)
- **21 colonnes** d'origine
- **37 tags uniques** au total
- **Format** : JSON (un fichier par échantillon)

### Colonnes Principales

#### Métadonnées du Problème
```
prob_desc_description       : Description textuelle du problème algorithmique
prob_desc_input_spec        : Spécification des entrées
prob_desc_output_spec       : Spécification des sorties
prob_desc_sample_inputs     : Exemples d'entrées
prob_desc_sample_outputs    : Exemples de sorties
prob_desc_notes             : Notes additionnelles (27% manquant)
difficulty                  : Niveau de difficulté (800-3500, 0.78% manquant)
prob_desc_time_limit        : Limite de temps d'exécution
prob_desc_memory_limit      : Limite de mémoire
prob_desc_created_at        : Timestamp de création
```

#### Code Source
```
source_code                 : Code Python solution (CIBLE pour features)
lang                        : Langage (Python 2/3, PyPy 2/3/3-64)
exec_outcome                : Résultat d'exécution (PASSED/FAILED)
```

#### Cible
```
tags                        : Liste de tags algorithmiques (VARIABLE CIBLE)
                             Exemples: ['greedy', 'math', 'implementation']
                                      ['graphs', 'trees', 'dfs and similar']
```

#### Identifiants
```
src_uid                     : ID unique du problème
code_uid                    : ID unique de la solution
file_name                   : Fichier source (train_000.jsonl, etc.)
```

## 5. APPROCHE PROPOSÉE

### 5.1 Feature Engineering
**Features Textuelles (Description) :**
1. TF-IDF (uni/bi/tri-grammes, max_features=5000-10000)
2. Features binaires (présence de mots-clés algorithmiques)
3. Longueur de la description

**Features Code Source :**
1. TF-IDF sur le code tokenisé
2. Features AST (nombre de fonctions, boucles, conditions, profondeur)
3. Longueur du code (lignes, caractères)
4. Imports utilisés

**Features Structurées :**
- `difficulty` (normalisé)
- `lang` (one-hot encoding)
- `exec_outcome` (binaire)

### 5.2 Modélisation
**Approche** : Classifier Chain avec XGBoost/LightGBM

**Justification :**
- Capture les dépendances entre tags (co-occurrence)
- Performant sur CPU
- Interprétable
- Gère bien les features sparse (TF-IDF)

**Gestion du déséquilibre :**
- Weighted loss (`scale_pos_weight`)
- Stratified split multi-label
- Potentiellement MLSMOTE pour tags rares

### 5.3 Métriques
- Micro F1-Score (métrique principale)
- Macro F1-Score (équité entre tags)
- F1-Score par tag (identifier les mieux/moins bien prédits)
- Hamming Loss

## 6. QUESTIONS POUR CHATGPT

### 6.1 Validation de l'Approche
1. **L'analyse EDA est-elle complète ?** Y a-t-il des analyses manquantes critiques ?
2. **Les features proposées sont-elles pertinentes ?** Manque-t-il des features évidentes ?
3. **L'approche Classifier Chain + XGBoost est-elle optimale** pour ce problème multi-label avec déséquilibre ?

### 6.2 Points d'Attention à Vérifier

#### Qualité du Texte
- **Formules LaTeX** : Les descriptions contiennent des formules `$$$...$$$`. Faut-il :
  - Les supprimer complètement ?
  - Les remplacer par des tokens spéciaux ?
  - Extraire des features (nombre de formules, complexité) ?

- **Langue** : Toutes les descriptions sont-elles en anglais ? Y a-t-il des caractères spéciaux problématiques ?

- **Nettoyage** : Le nettoyage actuel (suppression LaTeX, caractères spéciaux, lowercase) est-il suffisant ?

#### Exploitabilité des Variables
- **`prob_desc_notes`** (27% manquant) : Faut-il l'utiliser malgré les valeurs manquantes ? Imputation ou suppression ?

- **`difficulty`** (0.78% manquant) : Imputation par médiane du tag ou suppression des 39 lignes ?

- **`exec_outcome`** : Est-ce une feature pertinente ? Risque de data leakage ?

- **Différences Python 2/3** : Faut-il normaliser la syntaxe ou simplement utiliser `lang` comme feature catégorielle ?

#### Code Source
- **Parsing AST** : Risque d'erreurs de parsing (SyntaxError) ? Comment gérer ?

- **Imports** : Faut-il créer des features binaires pour chaque import courant (collections, itertools, math, etc.) ?

- **Commentaires** : Faut-il les supprimer avant TF-IDF ou les conserver (peuvent contenir des indices) ?

### 6.3 Stratégies Alternatives
1. **Filtrage du dataset** : Faut-il ne garder que les 2678 échantillons avec au moins un tag prioritaire, ou utiliser tous les 4982 ?

2. **Gestion des tags rares** :
   - Accepter une performance moindre sur `games` et `probabilities` ?
   - Techniques spécifiques (focal loss, MLSMOTE) ?
   - Regrouper certains tags ?

3. **Approches alternatives** :
   - Binary Relevance (plus simple, baseline) ?
   - Label Powerset (si peu de combinaisons uniques) ?
   - Sentence Transformers (all-MiniLM-L6-v2) pour embeddings sémantiques ?

### 6.4 Optimisations
1. **Réduction de dimensionnalité** : PCA/TruncatedSVD sur TF-IDF pour accélérer l'inférence ?

2. **Feature selection** : Techniques pour identifier les features les plus importantes ?

3. **Ensembling** : Combiner plusieurs modèles (TF-IDF+LR, TF-IDF+XGB, Embeddings+RF) ?

### 6.5 Validation
1. **Split stratifié** : La stratégie 70/15/15 avec `MultilabelStratifiedShuffleSplit` est-elle optimale ?

2. **Cross-validation** : Faut-il faire du k-fold CV multi-label ou un simple train/val/test suffit (contrainte de temps) ?

3. **Métriques** : Les métriques choisies (Micro F1, Macro F1, F1 par tag) sont-elles suffisantes ?
